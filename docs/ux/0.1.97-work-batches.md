# 0.1.97：已有作答批次与暂存

## 本批边界

从0.1.96接续Issue #19。教师显式选择已有学生作答，一批每生一份。批次只存引用，不复制图片或新建学生库；来源、匹配、AI原稿、正式评分及诊断继续由原管理器负责。没有新分析的作答可加入批次但不能在此触发模型循环，界面提示返回原流程。

`WorkBatchStore`复用学生管理器的私有根目录、身份验证、锁及原子文件写入。批次索引、每份作答的暂存与观察状态放在学生业务目录，均不纳入现有备课ZIP。成员选择读取所有已保存作答，不先截断最近50条。每次正式评分仍使用原revision校验；新元数据也检查版本，不把过期编辑写到另一学生。

## 暂存与教师状态

批次切换和返回明确暂存未记录输入；主动暂存/清除有独立操作，不是定时自动保存。暂存只保存与表单基线不同的字段，不把AI建议分写成教师分数。评分成功后仅清除已记录字段，其他题/诊断/情况输入保留。已有评分变化提示核对；原题匹配改变的旧暂存不自动套用。

未标记、待核对、资料缺页、未作答、尚未学到、作答时间不足和图像难辨是教师观察，不是分数；记录除清回未标记外需有依据。状态有修改历史，不自动归因或判零。不做班级均分/排名；后续汇总应明确同卷与有效样本分母。

## 界面

外层批次窗口嵌入既有StudentReviewDesk，维持原图与评分同屏。批次和学生位于顶部，当前学生加载失败时无旧图残留；未成功暂存或正在写正式记录时不切走。已有单份复核窗口仍可使用，它原先的内存切题保留不冒称已经获得跨窗口暂存。
