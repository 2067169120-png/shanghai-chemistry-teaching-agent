# 0.1.92 中文字体与显示检查

## 问题与本批范围

教师反馈“中文像用了英文字体，显示不自然”。0.1.91源码并非没有指定中文：应用请求Microsoft YaHei UI，主窗再选一遍字体，QSS还规定了另外一组字体和14px正文，部分提示为11px。问题不能简单归因为“名称是英文”；英文字体名称与是否包含汉字不是一回事。

本批消除多处字体选择、提高过小文字的字号，检查实际汉字绘制字体而不只看请求名称。Windows原生后端的分数缩放纳入专项验证。没有获取教师电脑的字体列表或显示设置，不推断其个人电脑唯一根因。

## 实现

- `desktop_workbench/typography.py`：应用创建后选择实际安装并覆盖中文样例的字体；Qt应用内只安装一次。Windows非原生后端缺少枚举时从本机Windows字体目录注册常规与粗体文件，不下载或分发。
- 全局样式移除font-family覆盖；正文11磅、小字至少9.5磅、标题适度加粗。菜单、输入框继承统一字体；原生Word阅读器与课堂自绘文字复用同一字体选择。
- 不关闭字符回退，化学上下标、箭头和特殊符号仍可使用本机合适的符号字形。符号字形来源不同不等于中文错误回退。
- 本机检查提供固定中文字例/化学符号示例，记录实际glyph-run字体、字号、DPR；不读取教师正文、路径、密钥。
- 不改原图、原Word、PPTX/DOCX渲染器、题目ID、题号映射或已生成文件。

## 验证方法

固定基线v0.1.91在同一Windows运行中取得实际字体记录，与新源码/独立程序报告并列。
新回归检查可用字体优先顺序、候选名不可用、中文覆盖检查、幂等初始化、控件抛光后实际字体一致、小字下限、化学符号和无敏感信息诊断。

源码与独立EXE在Qt原生Windows后端分别设置QT_SCALE_FACTOR=1、1.25、1.5，开窗检查字形、DPR和800×700保存/生成按钮位置，并保存原始截图尺寸。这是Qt倍率模拟，不是假称修改了Windows设置或验证了跨屏拖动。

整体结果只以本版机器报告为准。原923项覆盖中的功能继续回归，不把多次运行和本地子集相加。备份、作品、题序输出服务没有因为字体修复被替换。

## 尝试记录

最初单独字体基线工作流在临时脚本中未添加源码搜索路径，导入失败，没有产生可用字体结论。后改为显式从固定基线目录运行；失败记录保留。
本地字体专项和原生窗口专项完成后，尝试与其他Qt验收并行执行大回归进程时收到SIGKILL，未取得完整JUnit；该次不计为通过，未修改失败断言。最终Windows验证采用顺序执行。

## 参考

Qt官方QFont文档说明，请求的字体不保证就是每个字符实际绘制使用的字体，缺字时可以回退，实际字体可通过QFontInfo/字形运行检查：
https://doc.qt.io/qt-6/qfont.html

Qt官方High DPI文档说明设备独立坐标和QT_SCALE_FACTOR测试方式。Qt中的px并非一律物理像素，因此不把旧QSS的px单独归因为高DPI错误：
https://doc.qt.io/qt-6/highdpi.html
