# 0.1.89 备课备份：实现与验收边界

备份只选择现有personal-state中的备课草稿，作品分类、题篮引用、恢复表单；备课图片和已结束任务/返回稿/成品由教师明确勾选。它不是全工作台或全题库迁移，原Word/公众号导入库、学生业务、模型配置和密钥不在范围。正文中教师自己填写的个人信息不会自动脱敏；ZIP未加密。

恢复向新目录写入并核对文件路径、大小、SHA256、JSON和任务状态。标识最后写入，失败清理本次临时文件，不改当前作品。独立恢复窗口继续使用原有服务，可再次打开已经恢复的目录；不自动合并默认状态或续跑请求。补回备课图片要求原始内容、尺寸、格式相同，不按文件名替换。

## 实际发现与修复

首轮389项Windows回归通过，但全流程合成目录位于源码内，触发现有模型设置目录分离要求；将验收目标移至外部临时目录并增加提前提示，未放宽目录约束。

接续运行390项/393项回归通过，而完整恢复仍未通过。新增具体异常追踪后，Windows运行34824780560定位：TEMP中RUNNER~1短名称与解析后runneradmin完整路径指向同一位置，但只读任务读取器的根未规范化，误报“任务路径超出受控目录”。修复使备份只读读取器使用Path.resolve，与正常任务管理器一致；不是放松路径包含检查。增加等价路径和真实TEMP恢复回归。

本机已执行原生备份、恢复、查看原成品和补回原图，并增加“打开已有恢复目录”的取消/无效目录/不改当前表单测试。本机与Windows集合重叠，不累计；最终Windows和EXE是否通过、数量、源码SHA与截图以本版机器报告为准。

## 验收方式

使用隔离合成的当前/归档/回收站草稿、未完成表单、本地图片和生产渲染器成品：创建清单→保存ZIP→检查→独立恢复→重开窗口→原成品字节一致→从恢复的候选再导出→删除测试图片后按原文件补回。检查原草稿、分类、恢复文件和任务JSON未被改写。同一发行EXE另用--personal-state实际打开并关闭恢复窗口。

回归还检查坏ZIP、过期确认、路径越界、取消、写入失败、501份草稿和缺失材料；文件哈希只证明一致，不代表教学内容正确。没有真实API、教材蒸馏、原题库恢复或课堂质量验收；实际PPTX在Office中的视觉一致性仍未完成。
