# 原生桌面整合：交接与可验收任务

## 当前主线

版本基线0.1.82，基线提交25caa634；本轮整合0.1.83。仍使用现有PySide6、facade、Word原生服务、个人图片题服务、组卷与备课生成链。不再建立第二套Web前端、第二份题目身份库或一套只存在于报告里的生成提示词。

本轮核对了仓库、AGENTS、PR#1历史、源码和允许提交的派生知识。没有用户Windows文件系统权限，也没有向其他历史聊天会话发送任务的执行接口；因此本文件是供各任务共同引用的交接依据，不冒称其他会话已被调度。

首次启动修复、源码入口、任务首页、本地题库进度、课堂设计合同和Windows定向CI。具体操作与证据见根README；不把这些新增代码计作真实题库导入量。

## 下一批按教师流程收口

| 优先级 | 工作线与现有落点 | 本机验收动作 | 完成证据 |
| --- | --- | --- | --- |
| P0 | 启动 / desktop_paths、app、main_window | 现有资料机与无原库环境分别启动；确认版本、关闭与重开 | 两种环境分别记录，不用旧EXE结果替新源码 |
| P0 | Word / desktop_word_questions、attributes、semantic_tags | 先从导入历史核对既有98份，不重复导入；生成当前进度JSON，按缺项批次补全标签 | 本机真实来源清单、候选/印刷题单位、四项标签覆盖与待核原因 |
| P0 | 公众号 / personal_visual_questions、visual_import | 每批对照完整原页检查题面、公共材料、答案、跨页及相邻题残片；保留新旧裁片 | 实际逐题预览与学生/教师导出，不以哈希相同代替裁图干净 |
| P0 | 教材映射 / curriculum_workbench | 核对教材版本、册、章、节；适用年级与原试卷年级分开 | 原章节身份和证据位置；无出处的考试类型保持未知 |
| P1 | 统一选题与组卷 / 既有题篮、Word与图片题服务 | 同一知识点分别选Word题和图片主题；带公共材料进入混合题篮，导出两版 | 完整题目能解答、学生版无答案、不重画已有横线 |
| P1 | 教案/PPT / preparation_provider、pedagogy、renderer | 用同一份已选原教案和真实题篮生成一课时；逐页检查并改教学顺序 | 教案目标、活动、证据、用时与PPT对应；独练先于答案，字体图表可读 |
| P1 | 学情 / student_page、现有练习推荐服务 | 记录一次评分及教师诊断，推荐可核对题库ID，完成一次复练回写 | 题目身份与错因对应，复测日期和分数，不用单次错题定性长期能力 |
| P2 | 材料命题 / blueprint、review、图形模块 | 先做一套“材料→完整题干→答案→所需图形→学生/教师输出”样例 | 科学条件一致，图真正生成并查看；不是只列出需要画图 |
| P2 | 装置、有机图、热点 | 优先可编辑确定性SVG或结构化化学图；热点只选能映射教材且有来源的情境 | 图形连接/键型/电荷正确；时效素材标日期，不为追热点改变学科范围 |

P0和P1是本机下一批工作，不应继续被大量后台框架、审批层或汇报文档挤占。每次变更先说明教师在哪个页面少做了哪一步，再提供对应测试和界面/输出。

## 数据和提示词统一原则

题目层级沿用整卷→主题大题→印刷题→作答单元。摘取小问之前，先确定公共材料、符号定义、图片和前序结果是否闭合；信息不足则选整题或换题。Word有正文就走原生提取，旧OLE/WMF缺口回原件核对。图像无法靠文字API识读，能力提示按实际型号和请求验证，不能只按厂商名字判断。

教材与教参的完整原文仍是源材料，精炼索引用于定位。提示词分为稳定教学规则、当前教材/教案检索片段、真实题目与图形引用、教师要求；不把几千题直接塞进一份永久系统提示词。新课堂合同接入已有TEACHING_SOURCE_RULES；其他会话修改Provider时应保留测试 `test_desktop_teaching_design_contract.py`。

## 分支和交接

整合分支通过PR进入现有feature分支，保留main和既有PR#1。各线提交应写真实来源范围、改动模块、如何从桌面操作、完成与未完成、测试集合是否重叠；不要用“全部通过”省略验证范围。截图由隔离空库CI产生，用户资料机截图另按实际权限处理。密钥只在个人模型设置使用，不进代码、测试夹具或文档。
